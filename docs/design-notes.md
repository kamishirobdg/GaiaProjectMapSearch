## 1. 全体像

### 1.1 4つのタブ

| タブ | 何をするか | 評価の単位 |
| --- | --- | --- |
| Map（`/board`） | シードから盤面を大量に作り、ハード制約で絞り、ソフト評価で並べて上位K件を出す | 母星色ごと（基本7色＋原始・小惑星） |
| Setup（`/setup`） | タイル配置をシードから作り、18種族それぞれにとっての価値を出す | 種族ごと |
| List（`/list`） | 保存した Map と Setup の組み合わせを4つの基準で提案する | 種族ごとの Map＋Setup |
| Total（`/total`） | Map 1枚と Setup 1つを選び、種族ごとに Map＋Setup を合算して並べる | 種族ごと |

Map は「全プレイヤーが同じ盤面を共有する」、Setup は「タイルは早い者勝ちで奪い合う」という
性質の違いがある。Map の評価値は母星色ごとなので同じ色の2種族は同点になり、種族の差が出るのは
Setup 側だけ（2026-09-19 時点の整理。種族ごとの Map 評価は改善要望 → 2.7 節）。

### 1.2 評価値の桁

- **Map の色ごとの評価値も Setup の種族ごとの評価値も「100前後」に揃え、足して200前後**
  （2026-07-31 に Map を、2026-08-04 に Setup を揃えた）。ゲームの得点に近い桁にして、
  Total で素直に足せるようにするため。
- Setup は VP 換算の合計を最後に `SETUP_SCORE_DIVISOR`（28）で割る。割り算は最後の1回だけ
  なので、内訳の和と合計は丸め前の値で一致する。
- 小数は Map 側では消してある（星系の 0.5 は色ごとの合計で丸める）。Setup 側は割り算で
  小数が出るので表示は小数第1位まで（1枚しか出ないカテゴリで種族差が消えるのを避ける）。

### 1.3 互換の鉄則

- 検索条件キー・保存データのキーは「無効時フィールド省略」のスプレッド構築
  （`...(x > 0 ? { x } : {})`）。新しい設定を足すときも同じ形にして既存キーをバイト不変に保つ。
  評価の仕組みを変えるときは、新しいフィールドを既定で含めて**別バケツ**に貯める
  （古い結果と新しい結果が同じ順位表に混ざらないようにする）。
- 回帰スナップショット（`scripts/__snapshots__/baseline.json`）は意図した差分だけを出す。
- localStorage の書き込みはユーザー操作のハンドラだけ（Strict Mode の二重実行対策）。

## 2. Map 評価

### 2.1 検索の流れとハード制約

```
seed → buildLogicalMap → extractForEval → checkHardConstraints → evaluateSoft → Top-K
```

| ID | 内容 | 既定 |
| --- | --- | --- |
| H0 | 同種惑星（基本7色のみ）の直接隣接禁止。基本版ルールの合法性 | 基本版で常時有効 |
| H1 | 同色の通常惑星どうしが `minSameColorDist` 未満に近づかない | 3 |
| H2 | 最外周にある同色の通常惑星が `outerSameColorMax` 以下 | 1 |
| H4 | 中央スロットには大型セクターのみ | LF のみ。既定は無効 |
| H5 | 連結した惑星クラスタの最大サイズ | 既定は無効 |

ハード制約を通る盤面は少ない。既定条件での通過率（2026-09-29 実測）: LF 4人 0.2%
（37,706シード中80）、LF 3人 0.7%、基本版は H2 上限1だとほぼ通らず（回帰スナップショットの
90盤面で0）、上限3で 2%。**ソフト評価は通った盤面にしか走らない**ので、評価の計算量は
あまり問題にならない（2.6 節の到達モデルの検討で確認）。

### 2.2 ソフト評価の軸（惑星ごとの点を色ごとに足す）

| 軸 | 何を測るか | 既定の評価指数 |
| --- | --- | --- |
| 最外周 outer | 盤面の最外周セルにある惑星。広がる先が少ない。**2026-10-04（eval_v4）から「欠けマス × w」**: 距離2以内の18マスのうち盤面に無いマス1つにつき w を引く（2.8 節）。それまでは惑星1つにつき −3 | w ＝ 0.5（最外周は辺7〜角10マス欠ける） |
| 外周 touch | 最外周に接するセルにある惑星。同じ「欠けマス × w」（外周は3前後欠ける）。それまでは −1 | 同上 |
| 船接触 scout | LF の船（探査船セル）から距離 R 以内の惑星。距離が1伸びるごとに 1 引く | 10（船ごとに別の値も可）、半径 3 |
| 船星系 scoutCore | 船接触惑星から距離1〜2にある惑星。**距離1〜2に船接触惑星が2つ以上ある惑星だけ**（2026-07-30 に 1つ → 2つへ） | 船ごと 3（距離2は 2） |
| ガイア近接 gaia | 通常惑星から距離1/2/3にあるガイア惑星を合算 | 5 / 8 / 3 |
| 星系 cluster | 隣接で連結した惑星の塊。大きさ n（次元横断は 0.5 で数える）を、含まれる各色へ色ごとに1回加点 | 1 × n |

- 既定値は **各軸が全体に占める割合を実測して** 船接触 > 船星系 > ガイア > 星系 > 最外周 > 外周
  の順になるよう決めた（2026-07-30。3p LF 24盤面で 31.2% / 27.0% / 23.4% / 13.9% / 3.3% / 1.2%）。
  このとき 船接触 6→10、ガイア距離2 3→8、距離3 1→3 に変えた。
- ガイア近接・星系は 2026-07-23 に基本版専用の軸として入れ（当時の既定 5/3/1）、
  2026-07-30 に Lost Fleet でも既定 ON にした（LF の検索キーが変わり別バケツになる、と
  提示したうえで）。
- **距離減衰 `DISTANCE_FALLOFF` = 1 は評価指数の桁と連動する**。「重み −（距離−1）× 1」なので
  重みだけ10倍すると減衰がほぼ消える。桁を変えるときは必ず一緒に変える（2026-07-31）。
- 船ごとの重みはセル座標ではなく船の識別子（twilight / eclipse / rebellion / tfmars）で引く
  （2026-07-30 修正。それ以前は常に既定値へフォールバックしていた）。

### 2.3 検索スコア（何を「良い盤面」とみなすか）

```
score = − wImbalance × std(7色の合計)  +  wColorPref × Σ pref(色) × 色の値
```

- **スコアの本体は7色の値の「ばらつき」だけ**。値の大きさそのものは順位に効かない。
  良い盤面＝どの色にも同じくらいの価値がある盤面、という定義。
- 色優遇/冷遇（pref）は任意。`wColorPref` は 2026-07-31 に 3 → 25。pref=1 で偏り項とほぼ互角、
  2 で優遇が主導、5 でその色だけで決まる、という目盛りに実測で合わせた
  （4p LF 300盤面: 偏り項の振れ幅 1747 に対し色の値の振れ幅 67）。
- 原始・小惑星（LF4種族の母星）は7色の軸に入らない。色優遇と List の種族優遇では
  「最良の1惑星×補正値」（2.4 節）を掛け先にする。

### 2.4 原始・小惑星（PROTO / ASTEROID）の扱い

- Lost Fleet は種族を4つ追加する（2026-07-30 ユーザー訂正。それ以前のコードの
  「LF は種族を追加しない」は誤り）。モウェイド人・スペースジャイアント＝原始惑星、
  ティンカーロイド・ダルカニア人＝小惑星。
- **最外周/外周は原始・小惑星の評価に効かない**（2026-07-30 ユーザー確定）→ **2026-10-04 に撤回**。
  端の罰点を「欠けマス × w」にしたとき、一貫性のため原始・小惑星にも掛けることにした（2.8 節。
  効果は −0.5〜−1.6% で、LF では端がほぼ効かないという前提と整合する）。
- **種別ごとの単純合算をやめ、「最良の1惑星 × 補正値 2.75」にした**（2026-07-31）。
  「複数がそこそこ優位であるより、船に近く星系にも近い最良の惑星が1つ」が望ましい、
  という判断。補正値は基本7色の「合計」と桁を揃えるためだけの係数。
- 2.75 は 2026-08-02 に調べて据え置き。PROTO と ASTEROID の最良値の差（34.8 vs 43.9）は
  個数の差ではなく置かれ方の質の差だったので、種別ごとに分けない。決め方を変えても
  2.75〜3.00 に入る。
- **2026-10-02 に補正値の廃止を決めた**（2.6 節）。LF4種族は開始建物が1つなので、最良の1惑星の
  値そのままが実態。

### 2.5 表示とマーカー

- 内訳表の列は 評価 / 船接触 / 船星系 / ガイア / 星系 / 最外周 / 外周 と枚数。列の合計と
  評価は必ず一致させる。原始・小惑星の行は開始地点1ヶ所の値（2.6 節）。最外周/外周は
  eval_v3 まで「-」だったが、eval_v4 からは罰点の値を出す（古い保存結果は「-」のまま）。
- 評価指数の「欠けマス罰点」の入力欄をクリックすると最外周・外周の両方の惑星がマークされ、
  ホバーに罰点と欠けマス数が出る（例「赤 / 最外周 −3.5（欠け7）」）。
- マーカーはセル単位（2026-07-30 に実測で確定）。タイル画像の中のセル位置は
  `artworkCalib.ts` の較正値で決める。グローバルなセル格子は再構成できない
  （24通りの回転規則を総当たりしても盤面が成立しない）ので、素の軸座標から画面位置を出す
  経路は使わない。

2. 標準種族も単純合計ではなく、最良の2ヶ所を主体にして残りは参考程度にすべき。

- 原始・小惑星はすでに「最良1惑星×2.75」だった。基本色の集計を変えると係数の意味が変わるので
  測り直しが要る、と報告 → **係数そのものを廃止**（2026-10-02）。
- 「最良2ヶ所の平均」は勧めない: 原始惑星は盤面に4〜5個しか無く2位が大きく落ちるので、
  個数の少なさで損をする合計の弱点が戻る。

**到達しやすさのモデル（ユーザー提案 2026-10-02 → 定数確定 2026-10-02 / 10-03）**

3位以下の同色惑星を一律の重みではなく「開始地点からの到達コスト」で重み付けする。

- 開始地点は、標準種族は2ヶ所、LF4種族は1ヶ所。残りの到達加重まで含めて総当たりで選ぶ
  （「自身の値の上位2」と違う開始地点が選ばれる色が 15〜40% ある）。
- 到達コスト ＝ 跳躍のコスト ＋ 踏み台のコスト（惑星を踏み台にした経路の最小値。Dijkstra）。
  - 跳躍: 距離1=0 / 距離2=1（通常の到達範囲）/ 距離3〜4=2（QIC で届く）/
    距離5=3（+3射程のブースター・船アクション）/ それ以上は不可。
  - 踏み台: その惑星に入植するのに要る改造の歩数。同色0、改造の輪で隣1・2つ先2・反対3、
    ガイア1、次元横断1、原始3、小惑星2。**「そこから次へ跳ぶとき」に払う**ので、目的の
    惑星そのものには掛からない。
  - 改造の輪は **テラ→酸化→火山→砂漠→沼沢→チタン→氷→テラ**（ユーザー確定）。
  - 複数の踏み台を踏む経路は 3〜6% しか無く、2つ目以降への補正を入れても結果は動かない
    → **単純な和**（2026-10-03）。
- **LF4種族に母星種別は無い**（LF ルール p7）。他の原始惑星は3歩、小惑星はガイアフォーマー
  消費なので、同じ種別でも改造が要る。標準惑星の歩数は種族で違う: ダルカニア人1、
  スペースジャイアント2、ティンカーロイドとモウェイド人は相手次第で1か3 → Map 探索の段階では
  相手が不明なので **既定は1**（2026-10-03）。ガイアはティンカーロイド・ダルカニア人・
  スペースジャイアントが QIC 2。
- 到達係数 ＝ **0.5 の（コスト−1）乗**（2026-10-03 確定）。コスト1＝通常の到達範囲＝割引なし、
  以降1段ごとに半減。同色惑星は H1 で距離3以上に離れているので、3位以下の惑星は最低でも
  コスト2（0.5）になる。

届くので特別扱いしたい）**。ゲームの手順では 距離2＝航法1で無料 ＜ 距離3＝QIC 1つ ＜
距離4＝航法1＋QIC か QIC 2つ ≦ 距離5 の順。跳躍コストの表を4通りで比べた（LF 4人、係数 0.5 の

同じ扱いが実在する差を隠していた。

**実装（2026-10-03、eval_v3。作業ブランチ、本番は未デプロイ）**

- `src/gaia/eval/reachCost.ts`: 改造の輪・跳躍コスト・入植コスト・到達係数・LF4種族の表・
  Dijkstra・開始地点の総当たり。定数は `reachCost.test.ts` で固定。
- `evaluateSoft.ts`: 惑星ごとに軸の値を持ち（`perPlanet`）、色ごとに開始地点を選んで重み付き和。
  軸の列は重み付き和を軸ごとに丸め、評価はその合計。星系の軸は「色ごとに1回」から「惑星ごと」へ
  （監査の `cluster.byType` には従来の値を残す）。原始・小惑星は LF4種族ごと

### 2.8 最外周・外周の扱い（2026-10-03 検討 → 2026-10-04 「欠けマス × w」で確定・実装、eval_v4）

2.6 節の集計を入れたあと、最外周・外周の扱いを実装と同じ評価関数で測り直した
（`scripts/_probe_rim.ts 60`。惑星ごとの値を取り出し、最外周・外周の扱いだけを差し替えて
開始地点の選び直しまでやり直す）。結論は末尾の「実装」。

**事実**

- LF では最外周・外周の惑星が開始地点になることが少ない（開始地点の 7%（4人）/ 12%（3人）、
  開始地点に外周を含む色は 14% / 24%）。船から遠くて正の値が低い（内側 28 に対し外周 12・
  最外周 8）ため。したがって**加算を強めても乗算にしても検索の並びはほぼ変わらない**
  （現行との相関 ≥ 0.99）。効くのは「外周の惑星を開始地点にせざるを得ない色」の値だけ。
- 基本版では開始地点の 38% が外周にあり（外周を含む色 65%）、扱いが並びを大きく動かす。
- 現行の加算（−3 / −1）では**値が負になる惑星が 3.5〜6.6% ある**。開始地点＋到達加重の集計では、
  3位以下の「参考程度」の惑星が負の値で色の値を引き下げる形になる。乗算なら 0 止まり。
- 周囲の欠け具合（距離2以内の18セルのうち盤面にある割合 c2）は、内側 1.00、外周 0.85、
  最外周 0.59（角 0.44〜辺 0.72）。手で作った最外周・外周の表と整合し、角と辺を区別できる。

**ユーザーの前提と回答（2026-10-04）**

- 「端のマイナスが大きく効くのは基本版だけで、LF ではほぼ効かない」はプレイ感に沿っている。
  **式をどう変えるかとは別に、最終的な影響度の確認でこの前提（基本版 ≫ LF）を判定基準にする**。
- 基本版と LF で同じ式である必要はないが、意図を説明できる一貫した式が望ましい。
- 原始・小惑星にも、効くなら掛けてよい（3）。参考程度の惑星が負になっても下限は要らず、
  参考程度にマイナスすればよい（4）。乗算の「負にならない」利点は不要。

**提案「欠けマス × w」（2026-10-04。同日 w ＝ 0.5 で Go）**

意図を一言で言うと「**端の開始地点は、通常の到達範囲（2マス以内の18マス）のうち盤面に無いマスの
数だけ、将来の広がり先（鉱山を置く惑星・同盟の衛星・パワーの授受）を失う**」。その欠けたマス
1つにつき w 点を引く（加算。負になってもよい）。

- 式: 罰点(p) ＝ w × （p から距離2以内の18マスのうち盤面に無いマスの数）。内側の惑星は欠けが
  無いので 0、外周（内側の輪）は平均 2.7 マス、最外周は辺で約 7、角で約 10。
- **現行の −3 / −1 は w ≈ 0.4 とほぼ同じ**（辺 7.4 × 0.4 ＝ 3.0、外周 2.7 × 0.4 ＝ 1.1）。つまり
  いまの既定値には「欠けマス1つ 0.4 点」という説明が付く。違いは角と辺が区別されることだけ。
- 基本版と LF で同じ式。影響の差は式ではなく盤面の中身から出る（LF は船の価値が大きく、端の
  惑星が開始地点になるのが 7〜12% しかない）。実測は 基本版 8〜10% ≫ LF 1% で前提どおり。
- 原始・小惑星にも同じ罰点を掛ける（一貫性）。効果は −0.4〜−1.6%（w 0.4〜0.5）で、LF では
  端がほぼ効かないという前提と整合する。
- 入力欄は「最外周 / 外周」の2つから「欠けマス1つあたりの罰点 w」1つへ。内訳表の最外周・外周の
  列は、最外周セル・外周セルの罰点をそれぞれ足した値を出す（内側のセルは 0 なので第3の列は
  要らない）。原始・小惑星の行も「-」ではなく値を出す。

**実装（2026-10-04、eval_v4。ユーザーの Go「w=0.5」）**

  `RIM_GAP_RING_CELLS` 18）で、`reachCost.test.ts` が半径5の六角形で 辺7・角10・1つ内側 3〜5・
  2つ内側 0 を固定。
- `evaluateSoft.ts`: `SoftParams.wRimGap`（0 / 省略＝罰点なし）。惑星ごとの罰点は1回で、最外周セルの
  惑星は「最外周」の列、それ以外（外周セル）は「外周」の列へ。**内側のセルは全テンプレで欠け0、
  最外周と外周は重ならない**ことを実測してからこの振り分けにした（欠けがあるのにどちらでもない
  セルがもし出ても外周の列に入れて、列の合計と評価が一致したままにする）。原始・小惑星にも同じ
  罰点を掛け、`startAccess.lf` と `extraStart` に outer/touch を持たせた。監査に `rimGap`
  （w・範囲・マス数・惑星ごとの欠けマス数）、`outerHits` / `touchHits` に欠けマス数と罰点。
  eval_v3 までの `wOuter` / `wTouch` は任意の旧フィールドにして、指定があれば加えて効く
  （古い調査スクリプト用。新しい検索キーには出ない）。
- UI: 評価指数の2欄 → 「欠けマス罰点」1欄。キーは「0 なら省略」。
  **入力欄は 2026-10-05 から10倍の整数**（既定 5 ＝ 最外周の角（欠け10）の惑星1つの罰点。
  辺 3.5、外周 1.5 に相当。ユーザー要望「微調整のとき小数を避けたい」）。内部値 `wRimGap` と
  保存キーは欠けマス1つあたり 0.5 のままで、画面で n / 10 に換算するだけ（`RIM_GAP_INPUT_SCALE`）。
  評価の式も結果バケツも変わらない。
  復元は無ければ 0。内訳表の原始・小惑星の行に最外周・外周の値（古い保存結果は「-」）。
  マーカーのホバーに罰点と欠けマス数。条件プロファイルの要約は新旧で出し分け。
- 回帰スナップショット: 150件中144件が soft のみの差分（placement / hard 不変）。船接触の列も
  6件動くが、罰点で開始地点の選び方が変わったぶん。
- **実装後の実測（`_probe_rim.ts 60`）**: 罰点の影響は 基本版 9.9% ≫ LF 4人 1.0% / 3人 1.3% で
  判定基準どおり。開始地点に端を含む色の値の変化は 基本版 −13.0% / LF −2.7% / −3.0%。並びの相関
  （eval_v3 比）は LF 0.999 / 0.998、基本版 0.975、最上位色が変わる盤面は 3.3% / 0% / 3.3%。
  原始・小惑星は −0.5〜−1.6%。実装と机上の案 G5 は開始地点が 420/420 色で一致し、値の差は
  軸ごとの丸めぶん（最大 2.8）だけ。
- **Map の桁（`_probe_map_values.ts 60`）**: 最上位の中央値 LF4人 113 / LF3人 103 / 基本版 41
  （eval_v3 は 113 / 103 / 42）。実質不変なので、Map の桁の議論（4 節）はこのまま進められる。

### 2.9 「周辺の多色の惑星」の軸の検討（2026-10-05、未決）

2026-10-02 に「最外周・外周の扱い」と並べて挙がった論点。「距離2以内にある他色の通常惑星の色数を
測ってから決める」としていたので、eval_v4 の上で測った（`scripts/_probe_multicolor.ts 60`。惑星ごとの
値に候補の加点を足して開始地点の選び直しまでやり直す。他色＝基本7色のうち自分以外の通常惑星で、
ガイア・次元横断・原始・小惑星は数えない）。

**事実**

| 位置 | 距離2以内の他色の色数（平均、10〜90%） | 惑星数 | 色数0 の割合 |
| --- | --- | --- | --- |
| 内側 | LF 2.6〜2.8（1〜4）/ 基本版 3.1（2〜4） | 2.8〜3.5 | 0.3〜1.3% |
| 外周 | 2.2〜2.5（1〜4） | 2.3〜2.6 | 0.3〜3% |
| 最外周 | 1.1〜1.4（0〜2） | 1.1〜1.4 | 14〜19% |

- 色数の分布は 1色 17〜21% / 2色 30〜34% / 3色 27〜29% / 4色 14〜16% で、**ほぼ全惑星が 1〜4色**。
  開始地点に選ばれている惑星の平均（2.5〜2.8）は全惑星の平均（2.3〜2.5）とほぼ同じ。
- **既存の軸と強く重なる**。惑星単位の相関は 欠けマス数と −0.46（LF）/ −0.64（基本版）、星系の
  大きさと +0.3 / +0.5。つまり「周りに他色が多い」は「端ではない」「星系に属している」の言い換えに
  近く、eval_v4 の欠けマス罰点と星系の軸がすでに拾っている。
- **加点にすると影響が大きすぎる**。色数 × 2 でも色の値の変化は LF 19〜20% / 基本版 59%、並びの
  相関は LF 0.96 / 基本版 0.73、最上位色が変わる盤面 LF 8〜10% / 基本版 30%。基本版は色の値が
  31 前後と小さいので、ほぼ全惑星に乗る 2〜8 点の加点が相対的に大きい。

| 案（w=2） | LF 4人 影響 / 並びの相関 / 最上位色が変わる | 基本版 影響 / 並びの相関 / 最上位色が変わる |
| --- | --- | --- |
| A 色数（距離2）× w | 19.7% / 0.960 / 10% | 58.7% / 0.729 / 30% |
| B 惑星数（距離2）× w（w=1） | 10.7% / 0.986 / 8% | 31.8% / 0.871 / 17% |
| C 改造の歩数で重み付け（1歩1 / 2歩0.5 / 3歩0.25）× w | 11.8% / 0.976 / 10% | 35.1% / 0.857 / 22% |
| D 色数（距離3）× w | 33.8% / 0.967 / 12% | 98.3% / 0.677 / 32% |

**選択肢**

1. **見送り（推奨）**。理由は上の3点（重なり・差が小さい・影響が大きすぎる）に加えて、ゲームの意味が
   まだ定まっていない（他色が近いのは入植先という機会でもあり、他家の母星が近い競合でもある）。
   端の惑星の弱さは欠けマス罰点が引き受けた。
2. 入れるなら **C（改造の歩数で重み付け、距離2）**。意味が「自分が入植しやすい他色の惑星」と
   一言で言え、色数より重なりが小さい。ただし基本版だけ w を下げる（LF 2 / 基本版 1 程度）必要が
   あり、評価の意味が変わるので eval_v5。
3. **種族ごとの計算（2.7 節）のあとで再検討**。改造コストが種族で変わる（ガイア・改造の初期研究、
   LF4種族の特例）ので、C の重みは種族ごとに計算してこそ意味が出る。色ごとの今の段階で入れると
   二度手間になる。

**ユーザーの前提（2026-10-05、プレイヤーの感覚。評価に反映するか否かは慎重に）**

1. 開始候補から改造の近い星（またはガイア・次元横断）へ入植し、さらにその次、その次と**一筆書きで
   入植地を広げられる**マップは評価が高い。広げていく入植地の周囲に改造の遠い星もあると、他家と
   影響を与え合えて（パワーの授受）なおよい。
2. 改造1歩の星が近くにあれば高いが、**2歩の星も同時に近くにあると、その色の相手と1歩の星を
   取り合う**ので高くはならない（下げるほどではないが上げもしない）。一般に2歩の星は自分の入植先に
   ならず、競争相手の入植地として近くにあることの評価は他より低い。
   → 符号が改造の歩数で変わる（1歩 ＋、2歩 ±0、3歩は無関係か競合）ので、「色数」や「惑星数」の
   ような符号なしの数え方は前提に合わない。

**開始地点の周り（距離2以内）での同居の実測**（60盤面、各 840 開始地点）

| | 1歩の他色あり | 2歩あり | 両方あり | 1歩だけ | 2歩だけ | どちらも無し | ガイアか次元横断あり |
| --- | --- | --- | --- | --- | --- | --- | --- |
| LF 4人 | 73% | 60% | 45% | 28% | 15% | 12% | 84% |
| 基本版 | 65% | 49% | 35% | 30% | 14% | 20% | 95% |

1歩の星がある開始地点の6割前後で2歩の星も同居しており（前提2の「取り合い」の状況）、前提どおりに
符号を付けると ＋ と ±0 が混ざって平均ではほぼ相殺される。差が出るのは「1歩だけ」の 3割弱と
「どちらも無し」の 1〜2割で、どちらも既存の軸（星系・欠けマス）と重なる位置の性質。

**判断（2026-10-05 ユーザー案、同意）: 見送り**。種族ごとの計算に移ったあとも見送る前提でよい
（改造の輪の距離は色の関係で決まり、種族で変わるのは歩数あたりのコストと LF4種族の特例だけ。
前提1・2の構造は種族ごとでも同じ）。再検討するとしたら「多色」ではなく「入植の連鎖（開始地点から
改造1歩・ガイア・次元横断を踏んで広がれる範囲）」を符号付きで測る別の軸として。いまの集計は
踏み台の改造歩数を到達コストに入れているので、連鎖の「通りやすさ」は同色の到達加重に部分的に
入っている（踏み台そのものの価値は入っていない）。

## 4. 合算と提案（List / Total）

- **List の4基準**は種族別評価値の並びを1つの数に畳む式。逆優位＝Map 上位3種族の合計を小さく、
  優位＝Map 上位K種族の平均を大きく、上位バランス＝上位K種族が拮抗、全体バランス＝全種族の
  散らばりを小さく。添え物の係数 0.2 / 0.3 は「主項が同じ候補の順番を決める」程度の目分量
  （据え置き）。
- **優遇/冷遇の目盛り**は3タブとも「0=効かない / 1=基準とほぼ互角 / 2=優遇が主導 /
  5=実質それだけで決まる」に実測で揃えた（2026-07-31）。Map `wColorPref` 25、
  Setup `SETUP_COLOR_PREF_W` 0.3、List はその半分（掛け先が Map＋Setup で約2倍の大きさ）。
- **合算比**（2026-09-19 案C）: Total の合計列、List の種族優遇の掛け先、「合計の上位」が同じ比
  を使う。既定 1:1 は未決。2026-09-20 に「Map を3倍にして 1:1」案を検証 —— 合計の順位は
  合算比 3:1 と同じ。基本版の Map 最上位 55 に対し LF は 135〜149 なので一律3倍は LF で Map が
  支配する。2026-09-27 の提案は「基本版だけ Map ×2」だったが、Map 評価の見直し（2.6 節）で
  桁が変わるので、その後で決め直す。
- **合計の上位**は人数+2色、同じ色は強い方の種族だけ（2026-09-20。同色の2種族は卓で1人しか
  選べない）。
- 内訳を持たない古い Map 候補は Map ぶんが 0 になる（再検索かピン留めの作り直しで解消）。
