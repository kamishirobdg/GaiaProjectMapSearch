# 基本版マップ生成 仕様書（3・4人先行／確定版）

作成: 2026-07-26。§6の確認4件は 2026-07-23 に回答済み（各所に反映済み）。
出典: 基本版ルールブック p19「上級準備：最初のゲームを超えて」
（可変的なゲームボード／3・4人プレイ）＋ p4（最初のゲームの配置図）。
ソロ（オートマ）・1〜2人プレイ・手番順変更・勢力選択はスコープ外。
ユーザー決定（2026-07-23）: **3・4人のみ先行実装**。

## 1. ルール上の定義（p19）

- 宙域タイルは **10枚すべて**を使用。**05・06・07 は数字が実線の面**（=表面）。
  基本版の 3人と4人は**同一の盤面構成**（人数差は初期配置のみで、マップ生成には無関係）。
- 配置方法は3種:
  - **方法1**: 01〜04 は最初のゲームの位置（p4の図）のまま、**05〜10 の位置だけをランダムに入替**。各タイルは自由に回転。
  - **方法2**: 方法1に加えて **01〜04 の位置も（内側4スロット内で）入替**。
  - **方法3**: **全10タイルの位置を全スロットでランダムに入替**。
- 回転: 全方法で「気に入るまで自由に回転」＝**各タイル 0〜5 の6値を探索変数**にする。
- **絶対制約（太字注意書き）**: 「**同じ種類の2つの惑星は、決して直接隣接してはいけません**」。
  - 解釈（✅確認済み 2026-07-23）: 対象は**基本7色のみ**。ガイア惑星・次元横断惑星は
    「種類」に**含まない**（ガイア同士・次元横断同士の隣接は許容）。
  - これは選好ではなく**合法性**の制約 → 生成器は違反盤面を出力してはならない
    （既存H1〜H5より上位の「H0: 合法性」として実装）。
- さらなる可能性（p19）: 任意の新形状も可・**3人時に09/10を除いた縮小盤も可**
  → 後回し（✅確認済み: 初期実装に含めない。将来 `base_3p_small` として別テンプレート化）。

## 2. 既存パイプラインへの載せ方

```
seed → placement生成(方法1/2/3の置換＋回転) → buildLogicalMapFromPlacement
     → extractForEval → H0合法性 + H2/H5（H1は任意の追加絞込み） → evaluateSoft → Top-K
```

### 2.1 テンプレート
- 新 templateId: **`base_34p`**（3人・4人共用。共有設定 expansion=base × players∈{3,4} から導出）。
- スロット: p4 の最初のゲーム配置図から **10スロットの slotCenters（評価側）と表示座標（表示側）**を新規作成。
  - 内側4スロット（01〜04の初期位置）と外側6スロット（05〜10）を区別してデータ化（方法1/2の置換範囲）。
  - **display↔eval 座標関係は LF と同じ恒久チェック**（scripts/check-coord-consistency.ts）に
    `base_34p` を追加して監視する。4p M2/M5事故の再発防止として、スナップショット前に必ず検証。
- セクター定義: `sectorTiles_base.ts` の 01〜10（05a/06a/07a=実線面）を使用。データは既存。

### 2.2 placement 生成（ssot/searchPlacementConfig.ts に追加）
- 入力: seed・方法(1|2|3)。mulberry32＋独立ストリーム（既存流儀）。
- 方法1: outer6スロットに 05〜10 を shuffleSeeded で割当。01〜04 は固定位置。
- 方法2: ＋inner4スロット内で 01〜04 を shuffle。
- 方法3: 全10スロットに全10タイルを shuffle。
- 回転: 各スロット独立に rotSeed 0..5（既存の rot 枠組みをそのまま使用。
  LF固有の Middle回転写像は適用しない＝基本版タイルは素直な60°回転）。
- **searchKey**: templateId=`base_34p` に加え、`placementMethod`（1/2/3）を**必ずキーに含める**
  （方法で分布が変わるため）。スカウト系 soft 重みは基本版では**フィールドごと省略**
  （スプレッド構築の既存ルール踏襲。既存LFキーへの影響なし）。

### 2.3 制約（Hard）
- **H0（新設・常時有効）**: 同種惑星の直接隣接禁止。対象は**基本7色のみ**
  （ガイア・次元横断・原始・小惑星は対象外）。LogicalMap の惑星セル全対について
  6方向隣接×同 planetKind をチェック。1件でも違反したら棄却。
  - タイル内部の印刷配置は常に合法なので、実質**タイル境界を跨ぐ隣接**の検査。
- H1（同色最小距離）: 基本版でも**任意の追加絞込み**として提供。
  **既定値=3**（✅確認済み: LFと同じ絞込みを既定でかける）。
- H2（最外周同色上限）: `base_34p` 用の outer/touch セットを templateSets.ts に新規定義して対応。
- H4（中央大型）: 基本版では**無効**（方法1/2が01〜04の内側配置を構造的に保証。方法3では
  「01〜04を内側に」という制約が欲しければ将来オプション）。UI非表示。
- H5（連結許容数）: そのまま適用可。
- 探査船（scout）: 基本版に存在しない → extract結果の scoutCells は常に空。

### 2.4 評価（Soft）
- 使用可: wOuter / wTouch / wImbalance（imbalanceMetric）/ colorPreference。
- **無効化**: wScout / wScoutCore / scoutRadius 系（UIごと非表示。soft オブジェクトから
  フィールド省略でキー互換）。
- 評価対象の色: 基本7色＋ガイア＋次元横断の扱いは LF と同一（planetTypeTotals 等は既存実装のまま）。

### 2.5 スナップショット
- regression-snapshot.ts の TEMPLATE_IDS に `base_34p`（方法1/2/3 × 固定シード）を追加。
  **既存 3p/4p_lostFleet のエントリはバイト不変**（追加のみ）を確認して baseline を同コミット更新。

### 2.6 UI
- 共有設定で expansion=base × players 3/4 のとき検索有効化（②で導入済みの導出テーブルに追加）。
- 「配置方法」セレクタ（方法1/2/3、既定=方法1。✅確認済み: 3種とも提供）。
  ツールチップにルール文の要約。
- Hard/Soft パネル: scout系・centerMode を base 時に非表示。
- 3人時の 09/10 除外オプション: 初期実装に**含めない**（✅確認済み。将来 `base_3p_small`）。

## 3. 実装順（見積り）

1. p4 配置図から base_34p の slotCenters／表示座標を採寸・データ化（座標整合チェック拡張込み）
   — **最重量・事故ポイント**。プローブスクリプトで LF と同じ検証手順を踏む。
2. placement 生成（方法1/2/3）＋ H0 実装＋ユニットテスト（H0境界: 境界跨ぎ同種隣接の検出）。
3. outer/touch セット定義 → H2/soft 接続 → スナップショット追加。
4. UI（導出テーブル・方法セレクタ・パネル出し分け）→ ブラウザ検証。

## 4. 棄却率の予期される問題

H0（同種隣接禁止）は回転総当たりを伴わない単純棄却だと棄却率が高い可能性がある。
対策候補: (a) シードごとに「置換は固定・回転のみ再抽選」を数回試す
（LFの既存 placement 生成に回転リトライの前例があれば踏襲） (b) 単純棄却のまま
trials を回す（診断カウンタ hardFailBy.H0 で実測してから判断）。実装時に実測して決定。

## 5. 明確にスコープ外

- 1〜2人プレイ（05b/06b/07b面・7枚構成）、オートマ、手番順カード、勢力選択、
  「さらなる可能性」の自由形状配置。

## 6. 確認事項（✅2026-07-23 全4件回答済み）

1. 同種隣接禁止の「種類」: **ガイア・次元横断は含まない**（基本7色のみ対象）。
2. H1（同色最小距離）の基本版での既定値: **3**（LFと同じ絞込みを既定でかける）。
3. 3人時の09/10除外オプション（縮小盤）: **後回し**（初期実装に含めない）。
4. 方法1/2/3: **3つともセレクタで提供**（既定=方法1）。
